② 每回合执行链路 agent-runtime.ts:100 stream() —— 一个会话同一时刻仅一个活跃运行

从用户发送一条消息到回合落幕的 10 个阶段；① → ⑩ 顺序执行，⑦ 之后进入流式循环。
1
解析配置AgentConfig 表取主 Agent 定义（内置 default / explore / code）+ 项目默认 Provider/Model → createModel
2
运行管控runService.start 一会话一运行（僵尸记录就地收尾）+ runHub 支持断线重连回放
3
装配 RunContext权限模式（confirm / auto_edit / full / plan）+ readOnly + 项目工具授权 + 全局禁用 + planGate + abort 信号
4
创建 DelegationHub（每回合一个）定义来自 SubAgentDefinition 表（内置 4 个 + 自定义）；挂到 runContext.delegate，Delegate 工具据此注入
5
创建 BackgroundTaskHubbash(runInBackground) 的后端；注册表跨回合存活，本回合只挂通知流
6
合成工具集（34 个工具）11 个 ToolProvider 经 registry 合并 → 策略过滤 → 审批门 / 计划门包装 → 交给 Mastra Agent（新增 generateImage 图片生成）
7
构建 Mastra Agentinstructions = Agent 指令 + 深度思考 + plan 指引 + 自动委派策略（已修复） + AGENTS.md/CLAUDE.md + 跨会话记忆；skills 注入；TokenLimiter；maxSteps 80/120
8
上下文加工附件落盘 attachments/ → 斜杠技能展开 → 超阈值压缩（历史摘要 + 近期消息，失败退回全文）
9
流式输出agent.stream → UI 流 tee 成两支：客户端分支（断开即止）+ 泵分支（持久化 + runHub 回放）；空闲看门狗 + 错误友好化
10
回合收尾 onFinish先存消息再 finish 运行 → 知识库自动总结入队 + 跨会话记忆生成（均后台、失败只记日志）

⑤ 委派触发机制与多阶段流水线 agent-runtime.ts（2026-10-13：自动委派 + 游戏流水线实测通过）

✅ 自动委派：运行时动态注入"委派策略" 主 Agent 默认姿态 = 编排者而非实现者；构建类请求（游戏/应用/带素材的交付物）无条件走流水线：① Delegate planner 出完整计划 + 素材清单契约 → ② 同一消息并行 Delegate artist（按清单精确路径生图）+ fixer（按计划写代码）→ ③ DelegateWait 收敛后自行组装验证。目录随定义动态生成，对所有 Agent 生效，停用全部子智能体时整段消失。
🎮 实测："生成一个贪吃蛇小游戏"（未提"委派"二字） planner 50s/3 步出计划 → artist 26s/3 步生成三张风格统一素材 → fixer 100s/4 步完成 index.html，主 Agent 仅编排收敛；浏览器实测游戏可玩、素材全部加载成功。
遗留：AgentFormSheet 的 subAgents 字段仍是死配置。设置页仍可编辑主 Agent 的 subAgents（那个"探索"子 Agent），但运行时从不读取该字段——真正生效的定义只在"子智能体"区块（SubAgentDefinition 表）。建议后续移除该编辑器避免误导。
