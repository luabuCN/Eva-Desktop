# 「记忆」模块：对话回合结束自动沉淀记忆

## 原理（这类功能的通用实现方式）

截图里那种"对话结束后自动在记忆模块添加本次记忆"，本质是 4 步闭环：

1. **回合结束钩子**：服务端在对话回合收尾处（本项目为 `agent-runtime.ts` 的 `onFinish`）触发一个后台任务，与聊天流解耦、不阻塞用户；
2. **轻量 LLM 总结**：用廉价快速模型把本回合对话压缩成一条简短 markdown 笔记，并参考已有记忆决定"新建"还是"合并进同主题笔记"；
3. **持久化**：笔记入库（本项目用 SQLite + Prisma）；
4. **前端感知**：UI 通过轮询发现新笔记 → 聊天流末尾渲染「N 条记忆更新」卡片 + 侧栏记忆列表可浏览；下次开新回合时把最近记忆注入系统提示，agent 就"记得"。

你的项目已有一条同构管线（知识库 wiki auto-ingest：`agent-runtime.ts:552` → `wiki-queue` → `wiki-llm` → wiki 页面），但没有聊天内卡片、没有右侧面板记忆标签，且 wiki 沉淀的是实体页而非轻量笔记。本方案新建**独立轻量记忆模块**（默认选项）：每回合增量更新、最近记忆摘要注入系统提示。

## 服务端改动

### 1. 新表 `MemoryNote`（双轨建表，项目规则：schema.prisma + db.ts ensureSchema 同步）
- `server/prisma/schema.prisma`：新增 model（id、projectId?、conversationId?、title、content、triggerMessageId?、createdAt、updatedAt；索引 `[projectId, updatedAt]`、`[conversationId]`；Project/Conversation 加反向 relation）；`Project` 加 `memoryAutoGenerate Boolean?`（项目级开关，仿 `wikiAutoIngest`）
- `server/src/db.ts` `ensureSchema()`：对应 `CREATE TABLE IF NOT EXISTS` + 索引 + `addColumnIfMissing` 加列
- 跑 `prisma generate`

### 2. 新模块 `server/src/memory/`
- `memory-llm.ts`：`generateMemoryForTurn({conversationId, projectId, fromSeq, toSeq})` —— 复用 wiki-llm 的 `loadConversationTranscript` 取对话稿，带上该项目已有笔记（id+标题+截断正文），`generateText({ model: await createModel("fast"), ... })`（照抄 `wiki-llm.ts:228` 形态）；输出 JSON `{action: "create"|"update"|"skip", noteId?, title, content}`，解析失败/闲聊无新知 → 静默跳过
- `memory-service.ts`：`listNotes` / `upsertFromGeneration` / `updateNote` / `deleteNote`；`isMemoryEnabled(projectId?)`（AppSetting `memory.autoGenerate` 默认开 + 项目级覆盖，仿 `isAutoIngestEnabledFor`）；`recentMemorySection(projectId)` 取最近 8 条、每条截断 ~400 字符，拼成「## 跨会话记忆」markdown 段

### 3. `server/src/runtime/agent-runtime.ts` 两处挂点
- `onFinish`（约 :552 wiki 入队旁）：同样以 `!isAborted && lastRunHasText` 为门槛，fire-and-forget 调 `generateMemoryForTurn`，`triggerMessageId` = 最后一条 assistant 消息 id（前端据此把卡片插到对应消息后，刷新/重进会话也能恢复）
- 系统提示组装处（约 :238-258 instructions 数组）：追加 `recentMemorySection(projectId)`（非空才加）

### 4. 新路由 `server/src/routes/memory.ts`，挂到 `app.ts`
- `GET /api/memory?projectId=&conversationId=` → `{notes}`
- `PATCH /api/memory/:id`（手动编辑标题/正文）、`DELETE /api/memory/:id`
- `GET/PUT /api/memory/enabled`（全局/项目开关）

## 前端改动

### 5. `web/src/api.ts`
- `MemoryNoteInfo` 类型 + `listMemoryNotes` / `updateMemoryNote` / `deleteMemoryNote` / `getMemoryEnabled` / `setMemoryEnabled`（照 `listConversationTasks` 的 apiFetch 一行式）

### 6. 右侧面板「记忆」标签 — `web/src/components/RightPanel.tsx`
- `RightTab` 联合类型加 `"memory"`；`RIGHT_TAB_ITEMS` 加 `{id:"memory", label:"记忆", icon: BrainIcon}`
- 新 `MemoryList` 组件（仿 `TaskList` 卡片列表）：笔记卡片 = 标题 + 相对时间 + 展开看 markdown 正文 + 删除；顶部一个"自动生成"开关

### 7. 数据轮询 — `web/src/App.tsx` SessionView
- 新 hook `useMemoryNotes(projectId)`：signature-skip 轮询（回合进行中 2s、空闲 8s、回合结束刷新一次，仿 tasks/runs 轮询模式）；结果传给 RightPanel 与 ChatPane

### 8. 聊天内「N 条记忆更新」卡片 — `web/src/components/ChatPane.tsx`
- 消息渲染循环（约 :576-589）里，若某笔记 `triggerMessageId === message.id`，在其后渲染 `MemoryUpdateCard`：`TurnChangesCard` 同款 Collapsible，标题「N 条记忆更新」，展开显示笔记标题/摘要，点击条目切换右侧面板到记忆标签（复用 `handleToolSelect` 的 setTab 模式，SessionView 传回调）
- 不新增 SSE data part：卡片纯由轮询数据派生，无需改动消息协议
